# fogbell is written in Go

## Context and Problem Statement

fogbell started as a port of a single-file Python relay (about 2,600 lines and 1,400 lines of tests,
standard library only, shipped as a script in a ConfigMap). Rust and Go were both on the table. Which
language does the product use?

## Decision Drivers

- The work is I/O-bound: a webhook, a few Slack calls, a few read-only queries. A few notifications a
  minute.
- The hardest piece of logic is reading rule expressions; a real parser beats a hand-written one
  ([ADR-0002](0002-expressions-are-read-with-the-metricsql-parser.md)).
- The neighbours are Go: Alertmanager, Prometheus, VictoriaMetrics, Flux and Kubernetes clients.
- The maintainers' other projects are Go, with one shared release pipeline.

## Considered Options

- Go.
- Rust.
- Python, kept as is.

## Decision Outcome

Chosen option: "Go", because the MetricsQL parser that vmalert itself uses exists only in Go, the
domain's types and clients are Go, and the release pipeline (GoReleaser, ko, cosign) is shared with the
maintainers' other projects.

### Consequences

- Good, because one static binary on a distroless image, a few megabytes of memory.
- Good, because a contributor from the Prometheus or Kubernetes world reads it without a new
  language.
- Bad, because Rust's enums would make the incident's states harder to misuse; Go relies on tests for
  that.
- Neutral: Python would have kept working; it was replaced to ship a versioned, signed image instead of
  a script in a ConfigMap, and to read expressions with a real parser.

### Confirmation

`go.mod` and `mise.toml` pin the toolchain; CI builds and tests with it.

## More Information

- 2026-10-29: accepted. Reopen if a dependency that only another language has becomes central, or if
  the incident state machine grows beyond what tests keep honest.
- 2026-10-30: the release pipeline is now the shared webgrip Forgejo one (ADR-0007), not GoReleaser and ko; the reasons above stand.
